# Checking the Docker images

The release workflow publishes the Security Shepherd Tomcat image to Docker Hub as [`owasp/security-shepherd`](https://hub.docker.com/r/owasp/security-shepherd). This page shows how to check what's inside an image you pull and where it came from.

## Image tags

| Tag | What it is |
| --- | --- |
| `X.Y.Z`, e.g. `4.0.0` | A release. Doesn't change once published. |
| `X.Y`, `X`, `latest` | The newest release in that line. Moves with each release. |
| `X.Y.Z-SNAPSHOT`, e.g. `4.1.0-SNAPSHOT` | The latest `dev` build of the version in progress. Moves with each push to `dev`. |
| `dev` | The latest `dev` build. Moves with each push to `dev`. |

Snapshot and `dev` images are untested pre-releases. For anything you rely on, use a release tag, or pin the image digest (`owasp/security-shepherd@sha256:…`).

## SBOM

Each published image carries a software bill of materials (SBOM) in [SPDX](https://spdx.dev/) format, generated by BuildKit when the image is built. It lists the operating system packages, Tomcat, and the Java libraries inside the Security Shepherd WAR.

Print it with Docker Buildx:

```bash
docker buildx imagetools inspect owasp/security-shepherd:4.0.0 --format '{{ json .SBOM.SPDX }}'
```

Save it to a file to feed it to other tools, for example to scan it for known vulnerabilities with [Grype](https://github.com/anchore/grype):

```bash
docker buildx imagetools inspect owasp/security-shepherd:4.0.0 --format '{{ json .SBOM.SPDX }}' > shepherd-4.0.0.spdx.json
grype sbom:./shepherd-4.0.0.spdx.json
```

[Docker Scout](https://docs.docker.com/scout/) reads the same SBOM, and Docker Hub shows its results on the tag's page:

```bash
docker scout sbom owasp/security-shepherd:4.0.0
docker scout cves owasp/security-shepherd:4.0.0
```

Security Shepherd is deliberately vulnerable training software. Scanners report on its dependencies, not on the training lessons and challenges, which are vulnerable by design.

## Build provenance

Each image also carries a [SLSA](https://slsa.dev/) provenance attestation: which source, Dockerfile and build arguments it was built from, and by which GitHub Actions run.

```bash
docker buildx imagetools inspect owasp/security-shepherd:4.0.0 --format '{{ json .Provenance.SLSA }}'
```

This SBOM and provenance are stored next to the image on Docker Hub but aren't signed, so they show how the image says it was built. They don't prove it.
